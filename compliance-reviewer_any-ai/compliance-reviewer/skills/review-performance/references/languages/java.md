# Language Signals — Java (Performance)

Local lookup table, not a standard. Use it to classify code and configuration for PERF-01 … PERF-08; cite the AZPE elements, never this file. If a library isn't listed and you can't classify it, add `localized-standard-gap: unrecognized library <name>` to `notes`.

| Area | Pass signals | Anti-patterns / fail signals |
|---|---|---|
| Concurrency model (PERF-02, SKILL.md step 2) | Spring WebFlux / Reactor (`Mono`, `Flux` handlers), Vert.x, Netty handlers, Micronaut / Quarkus reactive routes: **async-first**. Servlet / Spring MVC (including `spring.threads.virtual.enabled=true`), JAX-RS on servlet containers, Quarkus blocking (`@Blocking`) endpoints: **thread-per-request** | — |
| Caching (PERF-01) | `@Cacheable` / `@CacheEvict` / `@CachePut` with Caffeine (`expireAfterWrite`, `maximumSize`), Redis (`RedisCacheConfiguration.entryTtl`), JCache / Ehcache with expiry; Redis `INCR` / `MULTI` / Lua for shared counters; `mget` / pipelining for several keys | `static HashMap` / `ConcurrentHashMap` caches without bounds; `spring.cache.type=simple` or `ConcurrentMapCacheManager` (no TTL, unbounded) in production config; `@Cacheable` without eviction on data the app writes; `get` then `set` for shared counters |
| Non-blocking I/O (PERF-02) | Reactive drivers (R2DBC, reactive Mongo / Redis, `WebClient`) on async-first stacks; `CompletableFuture.allOf` / `Mono.zip` for independent calls with a dedicated bounded executor; `Schedulers.boundedElastic()` for unavoidable blocking calls; `flatMap(..., concurrency)` limits | `.block()` / `.blockFirst()` in WebFlux handlers; JDBC / `RestTemplate` / file I/O on event-loop threads; `CompletableFuture.get()` / `join()` in reactive code or request threads waiting on async clients; `Thread.sleep` in request paths; `parallelStream()` over remote calls |
| Client reuse and pooling (PERF-03) | HikariCP (`spring.datasource.hikari.maximum-pool-size` set); one `java.net.http.HttpClient` / `RestClient` / `WebClient` bean; Apache `PoolingHttpClientConnectionManager`; singleton `OkHttpClient`; shared Lettuce connection or `JedisPool`; singleton `MongoClient`, `KafkaProducer` | `DriverManager.getConnection` per request; `new RestTemplate()` / `HttpClients.createDefault()` / `new OkHttpClient()` per call; `MongoClients.create` or `new KafkaProducer` per request; connections not closed (no try-with-resources) |
| N+1 and chatty I/O (PERF-04) | `JOIN FETCH`, `@EntityGraph`, `@BatchSize`, `hibernate.default_batch_fetch_size`; `saveAll` with `hibernate.jdbc.batch_size`; JDBC `addBatch` / `executeBatch`; `BufferedWriter` | `FetchType.LAZY` collections accessed in loops or serialization (open-in-view); `findById` inside loops; `save()` per item in loops without batching; `Files.write(..., APPEND)` per item in a loop |
| Hot-path code (PERF-05) | `StringBuilder`; `static final Pattern`; `HashSet` / `HashMap` lookups; primitive streams; parameterized SLF4J logging | `+=` on `String` in loops; `Pattern.compile` / `String.matches` inside loops; `List.contains` on large lists inside loops; boxing in tight loops; `log.info` per item in large loops |
| Data retrieval (PERF-06) | DTO / interface projections; `Pageable` with `spring.data.web.pageable.max-page-size`; `@Version` optimistic locking; `@Query` with aggregation | `findAll()` followed by stream `filter` / `sum`; `FetchType.EAGER` on collections; `SELECT *` native queries; `PESSIMISTIC_WRITE` on hot rows without need; JDBC log appenders writing to the business database |
| Offloading (PERF-07) | `@Async` with a configured, bounded `ThreadPoolTaskExecutor`; JMS / Kafka / RabbitMQ listeners; Spring Batch; `@Scheduled` jobs for off-peak work | `new Thread(...)` in controllers; `Executors.newCachedThreadPool()` for request-triggered work; long CPU work inline in a controller |
| Scale-out and serving (PERF-08) | Spring Session (`spring-session-data-redis` / JDBC); `server.compression.enabled=true`; `server.http2.enabled=true`; `spring.web.resources.cache.*` for static resources | `HttpSession` attributes in a multi-instance deployment without Spring Session |
