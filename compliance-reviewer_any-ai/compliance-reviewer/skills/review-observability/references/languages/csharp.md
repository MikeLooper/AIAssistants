# Language Signals — C#/.NET (Observability)

Local lookup table, not a standard. Use it to classify code and configuration for OBS-01 … OBS-10; cite the standards elements, never this file. If a library isn't listed and you can't classify it, add `localized-standard-gap: unrecognized library <name>` to `notes`.

| Area | Pass signals | Anti-patterns / fail signals |
|---|---|---|
| Structured logging (OBS-01) | `ILogger<T>` with message templates (`LogInformation("Order {OrderId} placed", id)`), `[LoggerMessage]` source generator, Serilog / NLog with structured sinks, `AddJsonConsole()` | `$"..."` interpolation or `+` concatenation passed to `Log*`; `Console.WriteLine` / `Debug.WriteLine` for diagnostics |
| Log levels (OBS-01, OBS-10) | `Logging:LogLevel` sections in `appsettings*.json` per environment; Serilog `MinimumLevel` from configuration | errors logged with `LogInformation`; level hard-coded in code |
| OpenTelemetry setup, code-based (OBS-03, OBS-05) | `services.AddOpenTelemetry().ConfigureResource(...).WithTracing(...).WithMetrics(...).WithLogging(...)`, `UseOtlpExporter()` / `AddOtlpExporter()`, `ActivitySource`, `Meter` (created once, static or DI singleton) | `ActivitySource`/`Meter`/`TracerProvider` created per request; `AddConsoleExporter()` as the only exporter in production config; OTLP endpoint hard-coded |
| Zero-code (instrumentation mode) | `OTEL_DOTNET_AUTO_HOME`, `OTEL_DOTNET_AUTO_{TRACES,METRICS,LOGS}_ENABLED`, `CORECLR_ENABLE_PROFILING` + `CORECLR_PROFILER*`, `DOTNET_STARTUP_HOOKS`, `instrument.sh`; Operator annotation `instrumentation.opentelemetry.io/inject-dotnet` | — |
| Instrumentation libraries (OBS-03) | `OpenTelemetry.Instrumentation.AspNetCore`, `.Http`, `.SqlClient`, `.EntityFrameworkCore` (`AddAspNetCoreInstrumentation()`, `AddHttpClientInstrumentation()`) | outbound `HttpClient` created without instrumentation where the rest of the app is instrumented |
| Context propagation (OBS-02) | `Activity.Current` flowing through `async`/`await`; `Propagators.DefaultTextMapPropagator.Inject/Extract` for queues and custom carriers; logging scopes / `ActivityTrackingOptions` adding TraceId/SpanId | `Task.Run`/`ThreadPool` work started from a captured-and-cleared context; custom correlation header with no propagation on outbound calls |
| Metrics (OBS-04) | `Meter.CreateCounter/CreateHistogram/CreateUpDownCounter/CreateObservableGauge`; ASP.NET Core (.NET 8+) built-in `http.server.request.duration` | tags fed from user/request IDs or raw paths |
| Identity (OBS-08) | `OTEL_SERVICE_NAME` or `ConfigureResource(r => r.AddService(name, serviceVersion: ...))`; resource detectors packages | no service name (→ `unknown_service`); version hard-coded constant |
| Health checks (OBS-06) | `AddHealthChecks().AddCheck(...)` / `IHealthCheck`, `MapHealthChecks("/healthz/live", new HealthCheckOptions { Predicate = ... })` with tags separating live vs ready, `HealthCheckRegistration.Timeout`, `HealthStatus.Degraded` | single endpoint with dependency checks used as liveness probe; `ResponseWriter` returning check details/exceptions on an anonymous route (WAFO-37); a handler returning a constant 200 |
| Exception logging (OBS-09) | `logger.LogError(ex, "...")` (exception object first argument), `Activity.SetStatus(ActivityStatusCode.Error, ...)`, `Activity.AddException(ex)` (.NET 9+), global `UseExceptionHandler` / `IExceptionHandler` logging at Error | `LogError(ex.Message)` without the exception; catch-log-rethrow at every layer; `SetStatus(Ok)` on every span |
| Vendor SDK (equivalent) | Application Insights SDK (`AddApplicationInsightsTelemetry`), Azure Monitor OpenTelemetry distro (`UseAzureMonitor()`), Datadog / New Relic / Elastic .NET agents | — |
